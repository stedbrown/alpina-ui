# Alpina UI 1.0 checklist

Use this list when preparing the first stable major release. Record the release candidate commit and links to evidence as each remaining item closes.

- [x] Define the supported package entries, component stages, SemVer rules and deprecation window. [API policy](api-stability.md)
- [x] Add a machine-checked declaration report and require a public change note when it changes. [Report](../etc/alpina-ui.api.md)
- [x] Provide versioned installation, archive verification and a separately authorized release workflow. [Maintainer guide](npm-release.md)
- [ ] Review each Beta entry with its intended consumers. Promote it, keep a clearly labelled experimental contract, or announce a migration. [Component inventory](https://alpina-ui.vercel.app/status/)
- [ ] Review all deprecations in the candidate report and publish a 0.x → 1.0 migration guide with runnable examples.
- [ ] Verify the packed candidate with the oldest supported React/React DOM peers and the current supported React major in the three integration projects. Attach build and runtime results.
- [ ] Record a manual keyboard and screen-reader pass for file selection, the public-service workflow, forms, overlays and printed payment alternatives. Include Windows high contrast and at least one touch device.
- [ ] Have speakers of the four national languages review field errors, assistive announcements and administrative terms in their actual form context.
- [ ] Run the full build, types, API report, unit, browser, bundle, visual, framework and performance checks against the final candidate. Link the CI run and verified archive checksum to the release notes.
- [ ] Verify installation and rollback using the versioned downloads, then have a maintainer approve the first major publication.
